## Features

### 21. Open multiple images in finder/file explorer/a specific app — ✅ shipped (V2 P1)
_As built:_ the library's bulk toolbar gets two buttons for the current selection (works on
any selected/flagged photos): reveal in file manager, and open in the OS default app. Reveal
batches into one OS call — macOS Finder via AppleScript `reveal` of every item, Windows groups
by folder via `SHOpenFolderAndSelectItems`, Linux tries the running file manager's D-Bus
`org.freedesktop.FileManager1.ShowItems` and falls back to opening each distinct parent folder.
Open uses the OS default app per file (`open path1 path2 …` in one macOS call; one process per
file on Windows/Linux — no OS-level batching there). Docker gets a multi-path `/reveal` +
`/open` on the host helper agent (`tools/sortandpost_helper.py`), same token/root checks as the
single-file version. A confirm dialog appears above 200 selected for reveal / 25 for open
(reveal is one cheap call regardless of count; open can spawn one window per file). Choosing a
specific app to open with (not just the OS default) is **#22**, not built here.

- Once images are flagged for editing or otherwise selected, open those images or any selected images and select them in file explorer

### 22. Change default app to open — ✅ shipped (V2 P2)
_As built:_ Settings -> "Open with" saves a per-machine app path (`local/ui_prefs.json`, never
synced -- app paths differ across machines) that the library's Open button and the photo page's
Paths list launch instead of the OS default -- a single click, no extra menu, and it never
touches the system's own file-type association. "Browse…" opens a real directory+file listing (a
macOS `.app` bundle shows as a selectable leaf, not something to navigate into) -- on a native
run it lists this process's own filesystem directly, no separate helper agent required; under
Docker it goes through the host helper agent's `/listdir?files=1`. The helper's `/reveal` +
`/open` also take an optional `app` field for parity. Also landed in this pass: the library's
"marked for editing" filtered view (`mark=1`) now pre-selects every flagged photo on load, so
bulk actions need no manual checkbox clicking first.

### 5. Packaged distribution (no terminal, no Python) — ✅ macOS shipped (V2 P5); ✅ Windows shipped (V2 P6); AppImage = P7
_As built (macOS):_ `packaging/macos/build.sh` → a PyInstaller onedir `sortandpost.app` + DMG.
It bundles exiftool, torch and the image-format libs; CLIP weights download on first use.
It's a menu-bar app (open, pause/resume indexing, start at login, logs, quit) that
supervises the web server, which opens at `http://sortandpost.localhost:8080`. Quit stops
the indexer between files, publishes, releases the lock, and first offers to move
"Recently deleted" photos to the Trash. Ad-hoc signed; notarization is scripted for when a
Developer ID exists. See CLAUDE.md → "Desktop app".

_As built (Windows):_ `packaging/windows/build.ps1` → a PyInstaller onedir
`sortandpost.exe` (no console), a per-user Inno Setup installer
(`sortandpost-<ver>-setup.exe`, no admin prompt) and a portable zip. Same tray menu in the
notification area; Quit offers the Recycle Bin. Upgrading / uninstalling closes a running
copy cleanly first and refuses to replace files under one it can't close. Unsigned
(SmartScreen "Run anyway" on first launch).

- PyInstaller or Briefcase single-file bundle with a **vendored `exiftool`**
  binary and the rawpy / pillow-heif native libs.
- CLIP weights downloaded on first run (needs network once) rather than bundled
  (~600 MB).
- Produces a double-clickable `.app` / `.exe` / AppImage.
- Run in system tray and have an opening/shutdown procedure

### 23. User onboarding — ✅ shipped (V2 P4)
_As built:_ a `/welcome` wizard. A new computer only has to point at the shared folder
(cloud drive) and confirm its photo folders; an existing library's settings are adopted.
A brand-new library also asks scan speed, excluded folders, stacking (on by default) and
delete scope; everyone gets theme + season. Nothing is scanned until Finish. Machine-only
data now lives outside the shared folder (see CLAUDE.md "App-data layout").

- Run through an initial user onboarding
- Choose the following before scanning any images
  - Library location/locations
  - Where settings, database, etc should be stored
  - Slow or fast scanning for initial scan
  - If the user wants images stacked
  - Excluded folder names
  - Light, dark, or system theme, and the season palette (Auto by default — see #10)
  - What to do when deleting photos

### 24. Library grid selection UX — ✅ shipped
Found during P1 hands-on testing (2026-09-28). A grid tile (`_thumb_cell` in
`app.py`) is a `ui.link` to the photo page; only its small selection checkbox
(`_GridSelection.checkbox`) has its own click handler (`.stop.prevent`) for
select / shift-range-select. Clicking anywhere else on the tile just follows
the link. Two consequences:
- Shift-click only extends the range when it lands on that small checkbox —
  it should work from anywhere on the tile.
- Cmd-click / Ctrl-click on a tile opens the photo in a new browser tab (the
  browser's native modified-click behavior on an `<a>`) instead of adding it
  to the selection, like most gallery apps use Cmd/Ctrl-click for.
Needs a JS-level modifier check on the tile's click (shift/cmd/ctrl ->
`preventDefault()` + route to `_GridSelection`, otherwise let the link
navigate as today).

### 10. Design pass — round 2 — ✅ shipped (V2 P3)
_As built_ (user's feedback, 2026-09-28), in three PRs:
- **Seasonal themes** — Spring / Summer / Fall / Winter palettes (user-chosen, recorded verbatim
  in CLAUDE.md "Theming" and `themes.py`) × Light / Dark / System, plus **Auto** (season by

Still open from the original first-cut notes, if they come up: `/review` and `/photo` layout
fit / photo-page composition; the header's season glyph only updates on the next page load.

## Robustness & scale

### 15. Targeted subtree rescan on FS events
A `watchdog` event currently schedules a debounced **full** `scan_once`.
Correct, just not minimal — rescan only the affected subtree.

### 19. Windows pass — ✅ V2 P6
rawpy / pillow-heif / send2trash / `explorer /select,` reveal / Windows-compat
rating tags (`EXIF:Rating`, `XMP-microsoft:RatingPercent`) all have code
paths. _As built:_ the full test suite runs on Windows. It found and fixed: sync publish
(`fsync` needs a write handle) and pull (the working DB can't be replaced while SQLite holds
it; retry on sharing violations), "Download & index" matching roots with `/`, the scanner
following junctions, the exiftool idle timer on Windows' coarse clock, and a new sqlmodel
(0.0.45) rejecting naive EXIF datetimes (pinned `<0.0.45`, all platforms).

## Backlog — fix if it bites
Low-priority, deferred until a real library actually hits them.

### 12. Group-by infinite-scroll race
Collapsing a large section gives it ~zero height, so infinite scroll can race
to the end and a later Expand-all redraws many tiles at once. Fine at ≤25k
photos. Fix if it bites — e.g. pause auto-append after N all-collapsed batches.

### 17. ANN index for > ~25k photos
Semantic search is brute-force NumPy cosine over a memmap matrix — the design
target is ≤25k photos. Past that, add an on-disk ANN index (hnswlib /
sqlite-vec) **behind the existing search interface** — do not change the
interface.

### 18. Near-duplicate detection polish
dHash is weak on near-flat images (a solid-color frame hashes to all-zero, so
solid frames cluster). Real photos have gradients. Revisit only if it produces
bad duplicate groups in practice.
