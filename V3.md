## 8. Deployment — Docker / NAS / server mode  _(P6a–c)_

- Let's rethink the docker deployment and move that to V3 as well

V1/V2 shipped Docker as-is with **native as the default**. V3 turns the container into a
proper always-on server story. The release plan is `Docker.md`; it covers Security.md **H1**
(login, bind to localhost, Host/Origin checks) and **L2** (pinned builds). The deferred
**M1** (DNS rebinding / cross-site websocket), **M2** (helper `/open`), **L1**
(`storage_secret`) and **L3** (rate limiting) matter once server mode is the focus.

### Validate + harden the container path
- Actually run `docker compose up --build` end to end (never done yet): confirm
  the Dockerfile builds, real CLIP loads, NiceGUI serves, bind mounts work,
  EXIF writeback through a mount works, `send2trash` → managed-trash path fires
  inside a Linux container.
- Add a compose `healthcheck` (the `curl` is already in the image for this).
- Deps-only pre-layer in the Dockerfile so editing code doesn't bust the
  ~150 MB torch wheel layer on rebuild.
- Build from `uv.lock` like the desktop apps: Docker still runs
  `uv pip install --torch-backend=cpu .` because the lock's Linux torch is the CUDA build.
  Needs a CPU torch source in the lock (or a separate Linux lock).

### Headless server framing
- Document the intended shape: indexer + web UI on an always-on box (NAS /
  home server) chewing through the library 24/7; browse from a laptop; a
  second machine opens the same sync folder and runs **read-only** until the
  lock frees (already built — just needs to be the documented use case).
- `docker compose run --rm indexer --once` / continuous indexer-only mode is
  already there (`profiles: ["tools"]`); make it first-class.

### File-manager helper agent (Docker-only reveal)
- `tools/sortandpost_helper.py` exists and works. Ship the
  `launchd` .plist (macOS) and a `.bat` + Task Scheduler note (Windows) so it
  starts at login; a `/settings` panel showing helper status + a copy-paste
  install command.
- Native runs don't need this at all (reveal works in-process).

### Bind-mount performance notes
- Document that scanning a large library through a macOS/Windows bind mount is
  slow (virtiofs / gRPC-FUSE); recommend the native runtime for the initial
  index and Docker for steady-state on Linux / NAS.
