## 1. [x] Custom time picker gets stuck on an hour — Sonnet
- Why first: a bug in posting, the feature that touches the outside world; small, contained.
- Where: `src/sortandpost/posts_ui.py`, `_when()` (~line 970). The Date / Time inputs call
  `_apply` on every `change`, which saves and runs `_when.refresh()`. That rebuilds the
  `type=time` input while you're still typing, so the field loses focus / its partly typed
  hour. Likely cause, still to reproduce: stepping the hour updates the value, the rebuild
  resets the field, and the hour goes back.
- Fix direction: don't rebuild the custom inputs on their own change (update the summary
  label only, or apply on blur / a "Set" button); keep the slot grid in step.
- Why Sonnet: one function, clear hypothesis, easy to verify in the browser.

## 2. [ ] Delete returns to the page you came from — Sonnet
- Wanted: library → photo1 → photo2, delete photo2 → **photo1**. Library → photo1, delete
  photo1 → **library** (same filters / scroll).
- Where: `src/sortandpost/app.py`, photo page `_do_delete` (~line 2219) does
  `ui.navigate.to(lq.url())`. The ‹ › arrows and the stack filmstrip use `location.replace`
  (~lines 1980, 6160), so browser history never holds photo1. `history.back()` alone won't work.
- Approach: carry where you came from (e.g. a `from=<hash>` URL param set by the arrow /
  filmstrip navigation). After a delete, open that photo if it still exists and isn't missing
  here, else the library URL. Watch for: `whole_stack` delete scope removing photo1 too, and a
  delete started from a collection-linked photo page.
- Why Sonnet: one page, simple data. Needs care, not deep design.

## 3. [ ] Drag to reorder photos in a post — Opus
- Where: `src/sortandpost/posts_ui.py`; order changes today through `_move(h, step)` with
  ← → buttons (~lines 505, 588). Keep those as the keyboard / accessible path.
- Needs a drag library bundled with the app (no CDN, it runs offline), e.g. SortableJS served
  as a static file, plus a bridge that sends the new order back to Python, saves the post, and
  re-renders without fighting Vue (Sortable moves DOM nodes that Vue also owns: the usual
  source of "jumps back" / duplicated tiles bugs). Sent / partly sent posts stay frozen.
- Packaging check: the new static file must ship in the macOS / Windows / Linux builds
  (`sortandpost.spec`) and Docker.
- Why Opus: JS↔NiceGUI interop, DOM reconciliation pitfalls, packaging across 3 platforms. The
  same component could later replace the collection page's ← → (out of scope here).

## 4. [ ] CI: stop paying for GitHub Actions — Sonnet
- Finding: the repo is **public** now, and GitHub Actions on standard runners (ubuntu + macOS,
  as `.github/workflows/ci.yml` uses) are **free for public repositories**. Check the billing
  page first; this may already be solved, and only needs confirming.
- If minutes are still billed (or for faster feedback): add `tools/ci.sh` that runs the same
  gate as `ci.yml` (ruff check, ruff format --check, mypy src, uv audit, pytest with
  `HF_HUB_OFFLINE=1`), optionally the Linux leg in the Lima VM, and narrow `ci.yml` triggers
  (e.g. PRs only, or `workflow_dispatch`). Document it in `CONTRIBUTING.md`.
- Why Sonnet: shell script + YAML, no app code.
