## 1. [x] Custom time picker gets stuck on an hour — Sonnet
- Why first: a bug in posting, the feature that touches the outside world; small, contained.
- Where: `src/sortandpost/posts_ui.py`, `_when()` (~line 970). The Date / Time inputs call
  `_apply` on every `change`, which saves and runs `_when.refresh()`. That rebuilds the
  `type=time` input while you're still typing, so the field loses focus / its partly typed
  hour. Likely cause, still to reproduce: stepping the hour updates the value, the rebuild
  resets the field, and the hour goes back.
- Fix direction: don't rebuild the custom inputs on their own change (update the summary
  label only, or apply on blur / a "Set" button); keep the slot grid in step.
- Why Sonnet: one function, clear hypothesis, easy to verify in the browser.

## 2. [x] Delete returns to the page you came from — Sonnet
- Wanted: library → photo1 → photo2, delete photo2 → **photo1**. Library → photo1, delete
  photo1 → **library** (same filters / scroll).
- Where: `src/sortandpost/app.py`, photo page `_do_delete` (~line 2219) does
  `ui.navigate.to(lq.url())`. The ‹ › arrows and the stack filmstrip use `location.replace`
  (~lines 1980, 6160), so browser history never holds photo1. `history.back()` alone won't work.
- Approach: carry where you came from (e.g. a `from=<hash>` URL param set by the arrow /
  filmstrip navigation). After a delete, open that photo if it still exists and isn't missing
  here, else the library URL. Watch for: `whole_stack` delete scope removing photo1 too, and a
  delete started from a collection-linked photo page.
- Why Sonnet: one page, simple data. Needs care, not deep design.

## 3. [x] Drag to reorder photos in a post — Opus
- Where: `src/sortandpost/posts_ui.py`; order changes today through `_move(h, step)` with
  ← → buttons (~lines 505, 588). Keep those as the keyboard / accessible path.
- Needs a drag library bundled with the app (no CDN, it runs offline), e.g. SortableJS served
  as a static file, plus a bridge that sends the new order back to Python, saves the post, and
  re-renders without fighting Vue (Sortable moves DOM nodes that Vue also owns: the usual
  source of "jumps back" / duplicated tiles bugs). Sent / partly sent posts stay frozen.
- Packaging check: the new static file must ship in the macOS / Windows / Linux builds
  (`sortandpost.spec`) and Docker.
- Why Opus: JS↔NiceGUI interop, DOM reconciliation pitfalls, packaging across 3 platforms. The
  same component could later replace the collection page's ← → (out of scope here).

## 4. [x] CI: stop paying for GitHub Actions — Sonnet
- **Done 2026-11-15:** confirmed free (public repo). CI's red was `uv audit`; fixed by bumping
  Pillow / setuptools / certifi / filelock / opentelemetry-api in `uv.lock`. No local script added.
- Finding: the repo is **public** now, and GitHub Actions on standard runners (ubuntu + macOS,
  as `.github/workflows/ci.yml` uses) are **free for public repositories**. Check the billing
  page first; this may already be solved, and only needs confirming.
- If minutes are still billed (or for faster feedback): add `tools/ci.sh` that runs the same
  gate as `ci.yml` (ruff check, ruff format --check, mypy src, uv audit, pytest with
  `HF_HUB_OFFLINE=1`), optionally the Linux leg in the Lima VM, and narrow `ci.yml` triggers
  (e.g. PRs only, or `workflow_dispatch`). Document it in `CONTRIBUTING.md`.
- Why Sonnet: shell script + YAML, no app code.

## 5. [x] Next / previous week arrows in the post scheduling grid — Sonnet
- Wanted: keep the "Pick a date & time" option, but add ‹ › arrows beside the quick-pick grid
  to page through weeks, so a post can be scheduled more than a week out.
- Where: `posts.schedule_slots()` (`src/sortandpost/posts.py`, ~line 265) always starts at
  today. Give it a start offset (in weeks). Add the arrows to the "When" grid in
  `posts_ui._when()` (~line 1111; grid built ~line 1072).
- Watch for: no paging back before the current week; `slot_minute` stays stable for each day;
  past slots stay greyed out; keep the #1 fix (don't rebuild the custom inputs while typing).
- Why Sonnet: two functions and plain date math, easy to check in the browser.

## 6. [x] Filter by collection in the library — Sonnet
- Wanted: "Collection" as a filter on `/` beside stars / camera / folder / tags.
- Where: `LibraryQuery` (`src/sortandpost/library_view.py`). Add a `coll` field built the same
  way as `posted`: parse (~line 206), URL pairs (~line 250), `chips()` (~line 347),
  description (~line 376), and the filter in `resolve_view` (~line 464). Add a toolbar icon
  button with a popover listing the collections (tinted + count badge while active).
- Watch for: stacks (a stack matches when any member is in the collection, like `posted`); a

  saved-search round trip.
- Why Sonnet: follows an existing filter pattern step for step. Do it before #7, which reuses
  the `coll=` param.

## 7. [x] A photo opened from a collection browses that collection — Opus
- Wanted: open a photo from `/collections/<id>`, and ‹ › / ← → step through that collection in
  its own order, not the whole library.
- Where: the collection tile link (`app.py` ~line 2958) opens `/photo/<hash>` with no query,
  so prev/next walk the default library view. Pass the collection on the link (the `coll=`
  param from #6, plus "use collection order"). `photo_detail` (~line 1950) then takes
  prev/next from the collection's membership order, skipping photos missing here, instead of
  the `taken_at` view. "Back" and the delete-return (#2's `from=` trail; fallback) go to
  `/collections/<id>`.
- Watch for: stack top photo vs member lookup (`locate` / `neighbors`); the `_cached_view`
  cache key (collection order vs library order must not share an entry); a photo removed from
  the collection, or the collection reordered, while the page is open.
- Why Opus: it changes the photo page's prev/next, view cache and trail logic, which three
  earlier features (grid browsing, stacks, delete-return) depend on.

## 8. [x] Drag to reorder photos in a collection — Opus
- Where: the collection grid in `app.py` (`_move` ~line 2938, `_member_tile` ~line 2956).
  Reuse the post composer's SortableJS bridge (`posts_ui._SORT_JS`, `sp-reorder` event,
  vendored `/_sp/js/`; packaging already done in #3), saving through `reorder_collection`.
  Keep the ← → buttons as the keyboard / accessible path.
- Watch for: a drag must not also fire the tile's click (shift / ⌘-click select, or following
  the photo link); accept only a rearrangement of the same ids (like `posts.reorder`); the
  position-number badges update after a drop.
- Why Opus: #3 already solved the hard part (Vue/DOM interop + packaging), but the collection
  grid adds multi-select click handling and the tile link that must coexist with Sortable.
